# dealer — 汽车经销商权益机会排行榜库

纯进程内存的 Go 库，由上层直接调用。销售人员依据车辆估值与贷款结清金额
寻找换车客户；管理员可切换或回滚估值版本，后台重算与客户修改、排行榜
查询并发进行。

## 运行

```sh
go build ./...        # 编译
go test ./...         # 全部测试（含规模耗时验证，约 10s）
go test -race ./...   # 带数据竞争检测
go test -short ./...  # 跳过规模耗时验证
```

## API 概览

- `New(customers, versions, initialVersion)`：初始化客户清单、不可变估值
  版本与初始生效版本。构造时校验每个客户在每份版本下均可定价。
- `Modify([]CustomerUpdate) (revision, error)`：整批原子提交，产生全局
  递增的客户数据修订号；返回前已在当前发布版本下重算榜单。
- `Switch(versionID) (*SwitchHandle, error)`：受理一次切换（含回滚与
  重选当前版本），分配递增受理序号；后受理请求取代尚未发布的请求。
  `SwitchHandle.Wait()` 报告最终是 `SwitchPublished` 还是
  `SwitchSuperseded`。
- `Query() Board`：返回估值版本、客户数据修订号与前 50 名榜单（权益、
  分层、机会分）。
- `Close()`：停止后台重算 worker。

## 设计要点

- 权益 = 车辆估值 − 贷款结清金额（整数分）；±150000 分为正/负权益边界。
  机会分 = 50 + floor(权益/10000)，超过贷款期限 75% 加 10 分，截断到
  0–100。排序：机会分降序、权益降序、客户编号升序。
- 榜单不变式：已发布榜单始终精确对应 `(publishedVersion, revision)`。
  每次 `Modify` 提交后在写锁内即时重算（50k 客户约 5ms），查询为 O(1)
  快照读取，因此任何查询结果都等价于调用期间某一时刻的全量重算。
- 切换由单个后台 worker 处理：受理时仅登记最新请求；计算基于读锁下的
  客户快照在锁外进行；发布时若受理序号已被更新请求取代则丢弃，若期间
  客户数据有变化则在写锁内按当前数据重算后发布，保证发布结果包含发布
  前已提交的全部修改。

## 测试

- `compute_test.go`：负数向下取整、分层临界值、机会分截断、排名并列
  与前 50 截断。
- `dealer_test.go`：初始化校验、修改原子性；以独立朴素全量计算核对
  权益、分层、机会分与前 50 名。
- `switch_test.go`：重算与修改重叠（修改先在旧版本可见、发布后保留）、
  连续切换 A/B/A 且计算乱序完成（仅最后受理者发布）、发布前后并发查询
  的每个 (版本, 修订号) 组合均与独立计算一致。
- `perf_test.go`：50000 客户 × 20 版本 × 每版 10000 条估值记录下，持续
  每秒 100 次修改 + 100 次查询，p95 与最终切换发布耗时验证（实测修改
  p95 ≈ 6ms，查询 p95 ≈ 6ms，发布 ≈ 5ms，远低于 200ms / 5s 上限）。
